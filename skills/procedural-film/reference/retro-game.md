# Retro game

How to make a playable retro platformer from the starter game.
The starter is a one-level game called ROBOT RUN.
It keeps the core genre mechanics: small and big forms, a power-up, crates, bricks, coins, pipes, a checkpoint and a goal pole.
When this page and the code disagree, the code is right.

## Assembly

A game project is three overlays copied into one empty folder, in this order.

```sh
cp -R skills/procedural-film/foundation/. my-game
cp -R skills/procedural-film/retro/. my-game
cp -R skills/procedural-film/game/. my-game
npm --prefix my-game/tools install
npm --prefix my-game/tools exec -- playwright install chromium
```

The foundation brings the film engine and its tools.
The retro overlay adds the pixel kit (`src/pixel.js`), the sound chip (`src/chip.js`) and the TV frame (`src/crt.js`).
The game overlay adds the console, its levels and art, and the release tools.
A later overlay replaces a file of the same name, so the order matters.
Run every command below from the project folder.

## The config file

`src/game/00-config.js` is the one place the game names itself.
Every other file and tool reads `GAME.CONFIG` from it.

| field | what it drives |
|---|---|
| `title` | the title screen box, the page title, `og:title`, the attract film's closing caption |
| `slug` | the placeholder site `https://<slug>.vercel.app` and the Vercel project name when `vercelProject` is empty |
| `heroName` | the lives screen line "STARRING <heroName>" |
| `saveKey` | the browser save slot. It must be `<slug>.save.v1` |
| `legal` | empty by default. When set, it shows in the title and menu help rows, so on the share card too, and joins `description` in `og:description` |
| `description` | the `og:description` text |
| `order` | the level ids in play order. `tools/proof/full.cjs` walks this list |
| `firstLevel` | where NEW GAME starts, and which tape the attract film uses |
| `siteUrl` | the share URL. Empty means the `<slug>` placeholder, with a warning |
| `vercelProject` | the Vercel project name. Empty means `slug` |

Set `legal` when the game borrows a third party's character, logo or brand name.

## Adding a level

### 1. The definition

Add an entry to `DEFS` in `src/game/01-levels.js`.
The `map(w)` helper builds a grid of air over a two-row floor.
Its `put`, `pit`, `pipe` and `stack` calls write the map.
A map is 12 rows of equal width, at least 20 columns.
Tiles are 16 px.
Rows 0 to 2 stay empty for the HUD.
Keep the opening safe.
Holding right from the start for 120 frames covers about 12 tiles at walk speed (1.56 px a frame) and 19 at run speed (2.56 px a frame), so the first 19 tiles past the start hold no foe, pit or wall, and a new player learns to move; the e2e checks PW3 and PW8 rely on it.

The fields the engine reads:

| field | meaning |
|---|---|
| `id`, `name`, `world` | the level id, its title, and the world label on the HUD |
| `kind` | `'over'` (open air) or `'under'` (a cellar). It picks the tile set |
| `rows` | the 12 map strings |
| `time` | the clock in time units. `0` for a sub-area |
| `song` | the level song id in `src/music.js` |
| `start` | `{ x, y, drop? }`, the start position in px. `drop` starts him falling |
| `mid` | `{ tx, row }`, the checkpoint |
| `pipeDown` | `{ tx, to }`, a pipe he can enter, and the sub-area it leads to |
| `pipeUp` | `{ tx }`, the pipe he comes back up out of |
| `pipeSide` | `{ tx, row, to, at }`, a side pipe exit, its target level and arrival door |
| `pole`, `castle` | the goal mast column and the goal house's first column |
| `main`, `respawn` | for a sub-area, the level it belongs to and where a death sends him |
| `tokenBase` | a sub-area's first token number |
| `tokens` | optional `[tx, ty, bit]` token overlays |
| `camLock` | optional camera cap in px |
| `scenery` | `[[name, col, y?]]`, background art by sprite name |

The characters the engine understands:

| char | tile |
|---|---|
| `.` | air |
| `#` | ground |
| `B` | brick |
| `X` | hard stair block |
| `?` | crate with a coin |
| `M` | crate with the power-up |
| `N` | a 1UP block |
| `C` | a brick with several coins |
| `+` | a hidden 1UP block |
| `o` | coin |
| `g` | walker foe |
| `t` | token |
| `[` `]` | pipe rim |
| `{` `}` | pipe body |
| `h` `H` | side pipe mouth |
| `-` `_` | side pipe body |
| `j` `J` | side pipe join |
| `!` | the top of the goal pole |
| `\|` | the goal pole mast |
| `W` | cellar wall |
| `G` | cellar floor |

A character a system claims through its `spawn` hook is also legal, as long as `tools/levels-lint.cjs` lists it in `LEGAL`.

### 2. The play order

Add the id to `order` in `src/game/00-config.js` and to `GAME.GAME_ORDER` in `01-levels.js`.
The two lists must be equal.
A sub-area reached only by a pipe goes in neither.

### 3. The lint data

Add an entry to `tools/proof/levels.data.cjs`, keyed by level id.
Every key is optional, and a level with no entry still gets every generic rule.

```js
'1-2': {
  jumps: [
    { name: 'the pit at 40-42', from: [34, 39, 10], to: [43, 48, 10], kind: 'req' },
  ],
  changes: [
    { row: 6, col: 30, from: '.', to: 'B', rule: 'F4', why: 'a head bump before the pit' },
  ],
  routes: {
    token: { 0: ['over the brick row: jump from the step', '1-2'] },
  },
},
```

`jumps` lists every jump the level needs or offers.
`from` and `to` are `[firstCol, lastCol, row]` standing surfaces, with an optional `'lift'`.
A `'req'` jump is judged at walk speed and an `'opt'` jump at run speed.
`changes` records map cells that differ from the design sketch, each with the rule it keeps.
`defChanges` does the same for definition fields, with a `test` function.
`routes` says how each token (and each 1UP or multi-coin block, by `'col:row'`) is reached and which program proves it.
A `t` token's bit is its place counted by column, left to right, starting from `tokenBase`.
So the leftmost `t` in the map is bit 0.

Run the lint.

```sh
node tools/levels-lint.cjs
node tools/levels-lint.cjs --only 1-2
```

### 4. The route and the program

Add a route function to `tools/proof/programs/routes.cjs` and put it in `ROUTES` under the level id.
A route returns planner moves (`k.advance`, `k.search`, `k.wait`) from the level's first play frame to its goal.
`tools/proof/full.cjs` uses `ROUTES` to walk `CONFIG.order`.

Add a program file in `tools/proof/programs/`, modelled on `1-1.cjs`.
A program has a `name`, an `order`, `opts.start`, the `exit` events it must reach (`['flagpole']` for a level), a `build` that returns the moves, and an optional `check`.

### 5. The tapes

Plan the new programs and save their tapes, then re-plan the full run.

```sh
node tools/proof/levels.cjs --replan 1-2
node tools/proof/full.cjs --replan
node tools/proof/levels.cjs
node tools/proof/full.cjs
```

The tapes land in `tools/proof/tapes/<name>.nes.json` and `<name>.modern.json`.
Commit them: the gates replay them and fail without them.
After every re-plan of the first level, run `node tools/attract.cjs` before any gate, even when `firstLevel` is unchanged.

### 6. Dropping the cellar

The starter's cellar (1-1b) is optional. To drop it, remove all of these:

- the `'1-1b'` definition in `src/game/01-levels.js`, and the `pipeDown` and `pipeUp` on 1-1 that lead to it
- token 2 in the 1-1 `routes` in `tools/proof/levels.data.cjs`
- `r11b` in `tools/proof/programs/routes.cjs`, and its name in the `module.exports` line
- the `1-1-cellar` program in `tools/proof/programs/1-1.cjs`
- `tools/proof/tapes/1-1-cellar.nes.json` and `tools/proof/tapes/1-1-cellar.modern.json`

Then run `node tools/levels-lint.cjs` and the tape steps above.

## Adding a foe or mechanic

The engine has one seam, and new behaviour plugs in there instead of editing `10-engine.js`.
New files go in `src/game/` numbered 11 to 19, so they load after the engine and before the tape kit.

- `GAME.KINDS[name]` is a foe kind. The engine calls its hooks for every enemy whose `kind` is that name.
- `GAME.systems` is a list of systems. Each one can claim map characters and run code every frame.
- `GAME.K` is the kit a module may use: `rowTop`, `rowOf`, `cell`, `solidAt`, `headAt`, `setCell`, `bodyL`, `bodyR`, `bodyH`, `emit`, `setSong`, `addScore`, `pop`, `popOf`, `comboPoints`, `hurt`, `makeEnemy`, and the constants `Q`, `PH`, `BUTTONS`, `drawH`.

A kind can set:

| hook | meaning |
|---|---|
| `top` | body height in px (the walker's is 14) |
| `flier` | ignores blocks and other foes |
| `spiky` | hurts from every side, a stomp included |
| `move(W, lv, e)` | moves the enemy each frame |
| `onStomp(W, lv, e, p)` | what a stomp does |
| `sprite(W, lv, e, f)` | returns `[name, drawHeight, flags, pal]`, or nothing to hide it |

A system can set `name`, `spawn` (map characters to functions), `build`, `enter`, `pre`, `step`, `sprites`, `cloneLevel` and `cloneWorld`.
Any hook that is missing is skipped.

This hopper follows the pattern `15-tokens.js` uses.
It claims the `k` character, places a foe of a new kind there, and makes that foe hop.

```js
// src/game/12-hopper.js
(function () {
  'use strict'
  const FILM = (window.FILM = window.FILM || {})
  const GAME = (FILM.__game = FILM.__game || {})
  const K = GAME.K

  GAME.KINDS.hopper = {
    top: 14,
    move(W, lv, e) {
      e.vy += 0.25
      e.y += e.vy
      if (K.solidAt(lv, e.x + 8, e.y)) {
        e.y = K.rowTop(K.rowOf(e.y))
        e.vy = (lv.t & 63) === 0 ? -4 : 0
      }
      e.x += e.vx
    },
    onStomp(W, lv, e, p) {
      e.st = 'dead'
      e.t = 0
      K.comboPoints(W, p.combo, e.x + 8, e.y - 24)
    },
    sprite(W, lv, e) {
      return [e.vy < 0 ? 'foe_hopper_2' : 'foe_hopper_1', 16, 0, 0]
    },
  }

  const register = (sys) => {
    const i = GAME.systems.findIndex((q) => q.name === sys.name)
    if (i >= 0) GAME.systems[i] = sys
    else GAME.systems.push(sys)
  }
  register({
    name: 'hopper',
    spawn: {
      k(lv, tx, ty) {
        lv.ents.push(K.makeEnemy('hopper', tx * 16, K.rowTop(ty) + 16))
        return '.'
      },
    },
  })
})()
```

Check the signature of every kit function you call in `10-engine.js` before you rely on it.
Add `foe_hopper_1` and `foe_hopper_2` to `src/manifest.js` and draw them in `src/sprites.js`.
Register by name, as above, so loading the file twice replaces the system and never doubles it.
Store any per-level state on `lv`, and copy it in `cloneLevel`, or determinism fails.
`node tools/proof/engine-scenarios.cjs` runs every check twice, once with modules 11 to 19 and once without, so the bare engine must still pass.

For fuller worked examples, read `examples/claude-quest-game/src/game/12-foes.js` (three more kinds and the boss, which is a system with its own hit points and events) and `13-platforms.js` (lifts, springs and embers).
Those files use the old `CQ` global.
In a new game, write `GAME` wherever they say `CQ`.

## Sprites

The names in `src/manifest.js` are the contract.
The engine and `30-draw.js` ask for exactly those names, and a name with no art draws as a magenta box of its declared size.
Hero and foe sprites (`hero_*`, `foe_*`) use only the keys `1`, `2`, `3` and `.`, so the game can swap their palette.
Tiles may use up to four colours.

```sh
node tools/art-check.cjs
```

It checks that every manifest name has art of exactly its size, that every colour is an NES colour and at most three per map, and that the palettes are valid.

## Sound

`src/music.js` registers songs and effects on the chip with `K.define({ songs, sfx })`.
The chip notation and effect helpers are in `reference/retro-sound.md` and the header of `src/chip.js`.

### Songs

The engine switches to these song ids.

| id | when |
|---|---|
| `title` | the title screen |
| the level's `song` | play starts. An `'over'` level song opens with section `'intro'` once, then plays from `'A'` |
| `hurry` | the clock reaches 100. It is a 90-frame jingle |
| `<song>Fast` | after the hurry jingle, the level song at speed minus 1 |
| `death` | he dies |
| `gameover` | the last life is lost |
| `flag` | the course-clear fanfare at the goal, 168 frames |
| `credits` | the final card |
| `none` | silence: into a pipe, the goal grab, the clear card |

A new level song needs its `Fast` variant too.
`src/music.js` builds those for `overworld` and `underground` in one line, so add the new id to that list.

### Events

Every event the engine emits:
`start`, `levelstart`, `pause`, `unpause`, `cursor`, `continue`, `quit`, `jump`, `coin`, `bump`, `brick`, `sprout`, `powerup`, `oneup`, `stomp`, `kick`, `hurt`, `die`, `lifelost`, `gameover`, `checkpoint`, `token`, `pipe`, `flagpole`, `tally`, `firework`, `hurry`, `clear`, `credits` and `song`.
Each one that makes a sound has an effect in `SFX` under the same name.
`die`, `lifelost`, `gameover`, `hurry` and `credits` are answered by a song, so they have no effect.
A new event your own module emits with `K.emit` needs its own `SFX` entry.
An effect returns `{ pri, p1?, p2?, t?, n? }`, and it takes a channel when its priority is at least the one playing there.

### Checks

```sh
node tools/audio/game-audio.cjs
node tools/audio/melody.cjs --bars 8 overworld
```

`game-audio.cjs` proves every level song, its `Fast` variant and every engine song exists.
`melody.cjs` prints each melody bar by bar from the chip's own writes.
Paste its output into the originality record at the top of `src/music.js`, and compare it by note list against any score you know, so no melody is a copy.

## The attract film

The attract film is the game playing itself from the first level's tape.

```sh
node tools/attract.cjs
node tools/attract.cjs --check
node tools/render.cjs --out exports/attract.mp4
```

`tools/attract.cjs` reads `tools/proof/tapes/<firstLevel>.modern.json`, replays it on the engine, and writes `GAME.ATTRACT` into `src/game/21-attract.js`.
It also rewrites the block between `// <attract>` and `// </attract>` in `src/timeline.js`: the tape length, the frame the level song starts, its id and the closing caption.
`--check` writes nothing and exits 1 when either file is out of date.
`tools/render.cjs --out exports/attract.mp4` renders the film with its sound.
Without `--out` it writes `exports/<folder>.mp4`, named after the project folder, not the config slug.
The film never shows the title screen. To look at a title frame, run `node tools/site.cjs`, which renders it to `web/og.png`.
`src/scenes/01-game.js` sets `FILM.crt.buttonsAt`, so the controller on screen shows what the tape pressed.
Re-run `tools/attract.cjs` after any re-plan of the first level.

## The gates

```sh
node tools/gates.cjs
node tools/gates.cjs --site https://my-game.vercel.app
```

It runs 13 gates in order, prints each gate's last line, and stops at the first red.

1. `tools/check.cjs` runs the film checks, such as the media scan and frame determinism.
2. `tools/levels-lint.cjs` checks every level's rules and jumps.
3. `tools/art-check.cjs` checks the sprites.
4. `tools/audio/game-audio.cjs` checks that every song the game needs exists.
5. `tools/proof/engine-scenarios.cjs` runs the engine scenarios, with and without the 11 to 19 modules.
6. `tools/proof/levels.cjs` replays every level tape and checks its fingerprint, exit and that he never dies.
7. `tools/proof/full.cjs` replays a whole game per feel, title to final card.
8. `tools/proof/determinism.cjs` replays every tape several ways and checks that each run matches.
9. `tools/proof/clock.cjs` checks the fixed-step clock at refresh rates from 50 to 240 Hz.
10. `tools/proof/menu.cjs` drives every menu screen and checks the actions.
11. `tools/site.cjs` builds `web/` with the CSP, share meta and share images.
12. `tools/game-check.cjs` checks the built game page.
13. `tools/e2e/run.cjs` plays the site in a browser against the local server.

The gates need no network and no account.
Prove it with the network blocked:

```sh
FILM_NO_NET=1 NODE_OPTIONS="--require $PWD/tools/proof/no-network.cjs" node tools/gates.cjs
```

Any connection to a host other than localhost then throws.

## Deploy

```sh
node tools/deploy.cjs --dry-run
```

The dry run runs every gate, then prints each command a real deploy would run.
It never calls Vercel and needs no Vercel CLI.

Deploy for real only when the author asks, and only with the author's own signed-in Vercel CLI.

```sh
node tools/deploy.cjs
node tools/deploy.cjs --redeploy
```

A real run aborts when the project name already exists, runs the gates, creates the project, links and deploys `web/`, then runs the browser tests against the live site.
It never overwrites a project.
`--redeploy` deploys `web/` again to the project an earlier run created, named in `web/.vercel/project.json`.
`--skip-gates` runs only `site.cjs` first, and is for use straight after a green `tools/gates.cjs`.
Set `VERCEL_BIN` to point at a Vercel CLI that is not on `PATH`.
On Windows the script looks for `vercel.cmd`.

## Known limits

- The camera only scrolls forward, so he can never walk back to the left.
- A pipe exit that lands past a token means one run cannot collect every token. Each token is proven by its own level program instead.
- CONTINUE stays greyed out until the game has a second level, because the save only records a level beyond the first.
